# cc-retain-lab

CC_Codex 二期（26.11）**数据工程**产品线：**留存裁撤台**（FastAPI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**分区留存策略版本 → 到期扫描裁决 → 归档或销毁执行 → 策略与实物分区对账**

与现有六线正交（不是采集目录、ETL 管道、同步源、解析入库、编排流、种子摄取）。  
也不碰外仓常见指纹（Feed 归并 / 作业编排 / CDC 游标 / 质检签发 / 贴源-明细-汇总）。

## 领域

- **所属领域**：数据工程  
- **子方向**：数仓与数据湖（分区留存 / 裁撤闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、FastAPI、Uvicorn、SQLite |
| 前端 | 原生 JS 单页（全中文），青灰底 + 铜强调，顶栏导航（非绿侧栏克隆） |
| 测试 | pytest + httpx（本地秒级闭环，优先于 compose） |

## 基线主链

1. 现行留存策略（主题域 / 保留天 / 到期动作）  
2. 实物分区列表（在线 / 归档 / 销毁）  
3. 按基准日到期扫描 → 生成待执行裁决  
4. 单条裁决执行（归档写地址 / 销毁清零）  
5. 策略与实物对账报告  

## 策略换版与裁决绑定（26.11 增量）

**口径：裁决绑定开单快照，执行按快照，不按现行版偷换。**

- **开单快照**：扫描开单时把 `policy_version / keep_days / decided_action`
  一次抄进 `judgments`，并记 `snapshot_at`。之后无论策略怎么换版，
  这条裁决的绑定值都不再改写。
- **分开展示**：裁决页每行并列「绑定快照」与「在用版」，并给核对结论：
  `一致` / `缩天待重扫` / `延期待重扫` / `动作变更待重扫` / `已收口` / `在用版缺失`。
  策略页的「策略版本队列」逐个主题域列 `在用版` 与 `开单绑定版` 的条数，并单列待重扫。
- **换版处置（择定：重扫，不锁旧）**：本实验室明确选「重扫」这一条路，
  不做「锁旧口径继续执行」。下一次到期扫描时，开放裁决绑定版 ≠ 在用版的一律重扫：
  新版本下仍到期 → 作废旧单并重开（`superseded_by_id / supersedes_id` 链留痕，
  `disposition` 记「重扫作废 / 重扫重开」）；新版本下已不到期（延期）→ 只作废、不重开。
  执行中的单子不半途改写。
- **执行闸门**：绑定版被现行版取代且尚未重扫的开放裁决，执行接口直接 409，
  提示先重跑扫描，避免旧保留天落库。已完成的历史裁决按旧快照留痕，显示「已收口」。
- **并发占坑**：扫描在 `BEGIN IMMEDIATE` 写锁内完成「读在用版 → 判到期 → 开单」，
  `scan_jobs` 上有「进行中」部分唯一索引，`judgments` 上同一分区只允许一条开放裁决
  （部分唯一索引兜底）。两名试跑同时扫描时一名开单、另一名占用跳过，不会双写互盖。
  执行侧用条件更新认领，同一裁决并发执行只有一个成功。
- **可验**：`GET /api/scan-jobs/{id}` 返回逐分区编排明细
  （龄期 / 在用版 / 绑定版 / 处置），扫描摘要的开单·重扫·作废·占用数与明细同源。
  对应测试：`tests/test_version_binding.py`（缩天 / 延期 / 执行闸门 / 并发占坑 / 失败闭）。
- **历史库兼容**：启动时按需 `ALTER TABLE` 补列；清理历史重复开放裁决，
  回收超过 30 分钟仍「进行中」的扫描与「执行中」裁决，再建唯一索引。

预留切口（未做，供后续功能题）：生效窗定时、跨域依赖冻结、归档回灌等。
